## 1. Matemática verificada: el "libro" que se demuestra a sí mismo

Este es probablemente el cambio de medio más profundo que está ocurriendo en matemática. **Lean 4** con **Mathlib** permite escribir definiciones y demostraciones que la máquina verifica. Ya no es un nicho: Terence Tao y otros lo usan en proyectos reales de investigación. Hay dos piezas clave para producir conocimiento con esto. La primera es **leanblueprint** (de Patrick Massot), que genera un documento LaTeX navegable con un grafo de dependencias entre lemas: verde lo demostrado, azul lo pendiente. La segunda es **Verso**, el sistema de documentación de Lean para escribir textos donde cada fórmula está vinculada a código verificado.

Para tus modelos teóricos de finanzas o tus diseños de modelos matemáticos, un blueprint verificado es un producto cualitativamente distinto a un PDF. En criptografía el análogo es **EasyCrypt**, **CryptoVerif**, **Tamarin** o **ProVerif** para pruebas de seguridad, y **Cryptol/SAW** (de Galois) para verificar que una implementación coincide con la especificación.

## 2. Documentos computacionales: texto, código y resultados en un solo objeto

Es la evolución directa del paper. Lo más fuerte hoy:

- **Typst**: un reemplazo moderno de LaTeX. Compila en milisegundos, tiene un lenguaje de scripting real y mensajes de error legibles. LaTeX sigue siendo obligatorio para publicar, pero para apuntes, informes y material propio Typst es otra experiencia.
- **Quarto**: desde una sola fuente (Markdown + Python/R/Julia) genera paper en PDF, sitio web, libro, slides y dashboards. Es el pegamento ideal para alguien que ya usa Python, R y LaTeX.
- **marimo**: notebooks *reactivos* de Python, almacenados como archivos `.py` puros (versionables en Git sin el caos de JSON de Jupyter). Se exportan como apps web que corren en el navegador vía WebAssembly (Pyodide), sin servidor.
- **MyST / Jupyter Book**: para libros técnicos con referencias cruzadas serias.

## 3. Explicaciones explorables: la matemática que se manipula

Es la tradición de Bret Victor y de la revista *Distill*: el lector no lee que un parámetro cambia el sistema, lo mueve y lo ve.

- **Manim** (la librería de 3Blue1Brown, en su versión comunitaria ManimCE) y **Motion Canvas** para animación matemática precisa en video.
- **Penrose** (de Carnegie Mellon): escribís notación matemática y el sistema genera diagramas. Es muy interesante conceptualmente.
- **D3**, **Observable Plot** y **Observable Framework** para visualización de datos interactiva y sitios de datos estáticos.
- **Three.js**, **WebGPU** y **MathBox** para geometría 3D y visualización de campos, superficies y espacios de fases en el navegador.
- **GeoGebra** y la API de **Desmos** para incrustar construcciones interactivas rápidas.

Ya usás React y Mermaid. El salto natural es React combinado con D3/Three.js para construir tus propios "objetos explorables".

## 4. Simulación de alto rendimiento: laboratorios virtuales

Para tus proyectos de física y de finanzas cuantitativas:

- **JAX**: NumPy con diferenciación automática, compilación JIT y GPU. Permite simulaciones *diferenciables*, es decir, calibrar un modelo derivando a través de la simulación entera.
- **Julia** con el ecosistema **SciML** (DifferentialEquations.jl, ModelingToolkit): probablemente el mejor entorno que existe hoy para ecuaciones diferenciales, incluidas las estocásticas.
- **NVIDIA Warp** y **Taichi**: kernels de simulación física en GPU escritos desde Python.
- **Godot** o **Unreal Engine**, cuando la simulación quiere convertirse en experiencia inmersiva. Esto se conecta con tu ejemplo de los videojuegos, porque ahí está la frontera de "vivir" un sistema dinámico. **WebXR** permite llevarlo a realidad virtual desde el navegador.

## 5. Apps y herramientas: el conocimiento como instrumento

A veces el mejor formato para transmitir un modelo es una herramienta que el otro *usa*:

- **Streamlit**, **Panel**, **Shiny for Python** o **Dash** para dashboards analíticos.
- **QuantLib**, **vectorbt** o **NautilusTrader** como motores en finanzas.
- **SageMath** en criptografía, que sigue siendo imbatible para álgebra y teoría de números, y **Circom**, **Noir** o **halo2** si te interesan las pruebas de conocimiento cero, uno de los campos más vivos de la criptografía aplicada.

## 6. La capa de infraestructura y la capa de IA

Esto es lo que convierte herramientas sueltas en un sistema:

- **Reproducibilidad**: `uv` para Python (rapidísimo), **Nix** o **devcontainers** para entornos idénticos en cualquier máquina, **GitHub Actions** para compilar y publicar automáticamente cada vez que hacés push.
- **IA agéntica**: Claude Code y herramientas similares que leen tu repositorio entero y ejecutan tareas. Lo más potente es el **MCP** (Model Context Protocol), que permite conectar un modelo a tus propias herramientas: tu vault de Obsidian, el servidor de Lean, tus datos de mercado. En Lean hay además un ecosistema creciente de asistentes de demostración basados en LLMs, como LeanDojo o LeanCopilot.

## Dónde está el alpha real

Mi tesis es que el diferencial no viene de acumular herramientas, sino de dos decisiones de arquitectura.

**Primero, una sola fuente de verdad que se renderiza en múltiples formatos.** Un mismo modelo puede vivir como código en un repositorio. Desde ahí genera automáticamente el paper (Typst/LaTeX), la versión web interactiva (Quarto o marimo con visualizaciones), la animación explicativa (Manim), el dashboard (Streamlit) y, cuando corresponde, el núcleo verificado (Lean). Un cambio en el modelo se propaga a todo. Muy poca gente trabaja así, y es exactamente lo que tu historia de los medios sugiere: el mismo tema tratado en todos los formatos a la vez.

**Segundo, elegir el formato según la naturaleza del conocimiento.** Una demostración pide verificación. Un sistema dinámico pide simulación manipulable. Una intuición geométrica pide animación. Una estrategia pide un instrumento con datos reales. El error común es meter todo en el mismo formato, por ejemplo todo en notebooks o todo en Notion.

Para alguien que programa, Obsidian (archivos Markdown planos dentro de un repositorio Git, conectable a IA vía MCP) suele ser la opción que mejor se integra con todo lo demás.

## Una advertencia honesta sobre Lean en este libro

Mathlib tiene buena cobertura de teoría de grafos y combinatoria. En cambio, la homología simplicial está parcialmente formalizada y la homología persistente casi no existe. Formalizar el libro entero sería un proyecto de investigación en sí mismo.

Mi propuesta es usar Lean de forma **selectiva y estratégica**. Por ejemplo, formalizar la fórmula de Euler para grafos planares en el capítulo I, o propiedades combinatorias de complejos simpliciales. Así aprendés la herramienta con resultados del libro sin que se convierta en un cuello de botella. Más adelante, si te entusiasma, formalizar algún lema de persistencia podría ser incluso una contribución original.
